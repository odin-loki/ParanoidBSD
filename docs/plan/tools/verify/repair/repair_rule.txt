Review rule for this round: a second reviewer compares your result with the code. A formal contract that is WEAKER than the prose contract (it leaves out a return value, an error code or a condition that the prose states), or that the code contradicts, is a defect. Fix it one of two ways: strengthen the formal contract until it covers everything the prose says, or, when the formal language cannot say it (pointers, structs, calls), set contract to "" and make the prose contract complete and exactly true. The prose must state every return value and error path the code has and must not claim anything the code does not do. The "rejected because" text is a claim to CHECK against the code, not an order: if it is wrong, keep the annotation but make it more precise. Use action "drop" when the item is not a function defined in this code, and also when you cannot write an annotation you are confident is correct (it is then listed as dropped, not hidden).
