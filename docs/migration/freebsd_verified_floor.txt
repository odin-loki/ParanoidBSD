# Ports proved IR-equivalent to their C original on a FreeBSD host.
#
# tools/ci/run_freebsd_oracle.sh fails if the count drops below this number.
# It may only be raised, and only against a run that reported the higher
# figure. This one comes from run 9 (commit 435ef785f, FreeBSD 15.1,
# clang 19.1.7, scope lib/msun): 73 verified, 23 mismatch, 24 compile_fail.
# Run 12 (commit 96c555238, same host and scope) reported 88, up from 73:
# the oracle had been comparing against a build configuration nothing
# ships. -fno-exceptions restores `nounwind` and the attribute group whose
# absence shifted every later group number, and `mustprogress` is now
# normalised away like `noundef` already was. +15 ports, no pass changed.

# Run 21 (commit 0c7f5735a, same host and scope): 199, up from 88, with no
# change to any pass. --ir-limit went from 120 to 400. The cap was smaller
# than lib/msun, so 201 of its 321 files had been recorded `skipped_budget`
# - never compiled, never compared - and "88 of 120" was 88 of the first
# third of the library in discovery order. The other 86 were verifying all
# along and nothing had asked.
#
# From here the count is verified + committed. A port that is committed
# stops being a .c, so discover_sources() stops finding it and ir_equal
# falls by one; without the sum, landing a port would read as losing one.

# Run 27 (commit 7f5782656, same host and scope): 211 verified + 1
# committed = 212, up from 199, and again with no change to any pass. The
# oracle had been repeating -I{src.parent} on -idirafter; clang keeps the
# later of a duplicated search path, so every source in lib/msun/src was
# compiled against the host's math.h instead of the tree's. Fixing the
# duplicate is what these thirteen are - ports that were always equivalent
# and were being compared against the wrong header.
# THE SUM GAINED A THIRD TERM (run 36)
#
# lib/msun has no such removal on the record; the term is here because the ratchets are
# the same code and the next deletion may be in this scope.
#
# Run 34, the last green one, reported 122 verified + 1 committed = 123.
# Run 36 reported 96 verified + 26 committed = 122 and failed the floor by
# one. Twenty-five ports landed in between and verified fell by twenty-six,
# so exactly one file left the candidate set without becoming a port:
# hbsd/src/lib/libc/amd64/string/strnlen.c, which run 34 named in its
# committable list - IR-equal AND ABI-equal - and which commit 4f926059c
# deleted along with ten other arch-string sources that shadowed their
# machine-independent originals through .PATH and called assembly that was
# already gone. The ABI figures moved by the same one, for the same file.
#
# So a source has three ways out of the candidate set, not two: it can be
# ported (counted by `+ committed'), it can regress (which is what this
# floor is for), or it can be DELETED - neither a .c that verifies nor a
# .cpp that shipped. The third was not accounted for, and the honest fix is
# to complete the invariant rather than to move the number: this floor is
# unchanged, and docs/migration/freebsd_oracle_removed.txt names the
# deletion with the commit that made it. tools/check_oracle_removed.py
# holds every entry to what git says, so the term cannot become a way to
# hold a floor up over a file that is back.
