# Linuxulator Strategy (Wave 8)

**Status:** Scaffold — strategy frozen; implementation tracks HardenedBSD linuxulator.  
**Scope:** Binary Linux compatibility layer retained alongside native PBSD userland.

## Goals

1. Run unported Linux binaries (Steam, proprietary tools) without rewriting them in Wave 2.
2. Keep the linuxulator outside the native capability surface — Linux tasks never receive PBSD handles.
3. Coexist with BIFROST: Windows guest via SI-8 VmHandle; Linux ELF via linuxulator syscall shim.

## Architecture

```
┌─────────────────────────────────────────┐
│  KDE / native apps (PBSD handles)       │
├─────────────────────────────────────────┤
│  linuxulator (hbsd compat layer)        │  ← retained C from hbsd, wave9 inventory
├─────────────────────────────────────────┤
│  PBSD kernel (C++23 modules + bridges)  │
└─────────────────────────────────────────┘
```

## Migration stance

| Track | Action | Wave |
|-------|--------|------|
| Native utilities | Rewrite to C++23 modules | 2 |
| Linux-only closed source | Keep linuxulator | — |
| Linuxulator internals | Convert opportunistically after wave9 gate | 9+ |
| New syscalls | Capsicum bridge first; linuxulator shim second | 4+ |

## Isolation rules

- Linux processes run in a separate compat VM address space (existing FreeBSD model).
- No `VmHandle` or UDA MMIO grants cross into linuxulator tasks.
- BIFROST guest MMIO is SI-8 bounded; linuxulator does not share guest RAM mappings.

## Exit criteria (PBSD 0.1)

- Default desktop session does not require linuxulator for shipped PBSD apps.
- linuxulator package remains optional in release media for Linux binary compat.
- Inventory marks remaining linuxulator `.c` files under `wave9` with documented exceptions only (firmware/asm).
