# Modules that cannot be built on Linux
#
# PBSD targets FreeBSD/HardenedBSD. The modules listed here are ports of
# FreeBSD userland whose sources include headers that either live inside the
# FreeBSD tree (math_private.h, namespace.h, fpmath.h, quad.h, local.h) or do
# not exist on Linux at all (sys/sysctl.h, sys/acl.h, sys/proc.h, sys/mac.h,
# sys/linker.h, uuid.h, ieeefp.h, ssp/string.h).
#
# Pointing the build at hbsd/src/lib/libc/include does not help: those private
# headers transitively need FreeBSD's sys/*, which then shadows glibc and
# breaks far more than it fixes (149 failures becomes 174, or 603 once
# hbsd/src/sys is on the path). The list below is therefore the floor for a
# Linux build, not a backlog.
#
# What it is for: tools/check_linux_build.py fails CI when a module outside
# this list stops building. The list may shrink - it must never grow without
# a deliberate edit and a reason.
#
# One caveat about shrinking it. CMake compiles nothing until the whole C++20
# dependency scan succeeds, and the scan stops at the first wall of errors, so
# a Linux log usually covers only about half the 1,352 targets - which half
# depends on scheduling. An entry ninja never reached has not started building;
# check_linux_build.py reports those separately as "not reached" and refuses to
# --write from such a log, because rewriting from it would quietly delete
# exceptions that are still needed.
#
# Every entry is a FreeBSD-derived port under lib/, bin/, sbin/, usr.bin/,
# usr.sbin/ or sys/. No module original to PBSD appears here, and none fails:
# the handle nucleus, UDA, the analyser, BIFROST, the compositor, the theme
# and the KDE bridges all scan and compile on Linux.
#
# Regenerate after a toolchain change:
#   cmake -S pbsd -B build -G Ninja -DCMAKE_CXX_COMPILER=clang++
#   ninja -C build -k 0 2>&1 | tee build.log
#   python3 tools/check_linux_build.py build.log --write
#
# Baseline: clang 18.1.3, CMake 3.28.3, Ubuntu 24.04.
