# Ports proved IR-equivalent AND exporting the same symbols as their C
# original, on a FreeBSD host.
#
# The older floor next to this one counts semantic equivalence only, and
# normalize_ir() demangles names to get it: @_Z9usage_msgv compares equal to
# @usage_msg. That is right for "does this compute the same thing" and wrong
# for "can this ship". A function declared in a header keeps C linkage
# through __BEGIN_DECLS; one that is external but declared nowhere is
# mangled, and libm cannot ship a symbol under a new name.
#
# So this is the number that decides whether a port is committable, and it is
# a separate ratchet rather than a redefinition of the old one, because the
# old one still measures something worth not regressing.
#
# Run 12 (commit 96c555238, FreeBSD 15.1, clang 19.1.7, scope lib/msun):
# 74 ABI-equal against 88 IR-equal. The 14 in the gap are real: msun's
# __kernel_cosl, __kernel_sinl and __kernel_tanl in both ld80 and ld128
# compute the right answer and export _Z13__kernel_coslee instead of
# __kernel_cosl. lib/msun/src/math_private.h declares them with no
# __BEGIN_DECLS, so under C++ they get C++ linkage. Those ports are correct
# and unshippable, which is exactly the distinction this floor exists to
# make.
#
# Run 13 (commit fc34304a3, same host and scope): 88, equal to the IR
# floor. The gap closed entirely - adding __BEGIN_DECLS to
# lib/msun/src/math_private.h converted all 14 at once, which is what a
# single missing linkage guard being the whole cause looks like.
#
# 88 of 120 ports are now both semantically identical to their C original
# and exporting the same symbols. That is the committable set.

# Run 21 (commit 0c7f5735a, same host and scope): 174, from the same
# --ir-limit raise described in the sibling floor. 199 ports are IR-equal
# and 174 of those are ABI-equal, so the gap is back to 25 - and all 25 are
# one family:
#
#   C only  : fmaximum          C++ only: _Z8fmaximumdd
#   C only  : fmaximum_mag      C++ only: _Z12fmaximum_magdd
#   ... fminimum, _num, _mag_num, and the f/l variants
#
# Not the same cause as the 14 that closed in run 13. lib/msun/src/math.h
# declares all of them inside __BEGIN_DECLS, and the __ISO_C_VISIBLE >= 2023
# guard they sit behind does evaluate true under -std=c++23 (tested).
# The suspect is oracle_include_flags(), which adds the tree's headers with
# -idirafter rather than -I so that glibc wins the standard headers on
# Linux: `#include <math.h>` in s_fmaximum.c then resolves to the HOST's
# math.h, which on this runner may predate fmaximum entirely. If so the
# function is declared nowhere, C emits a plain symbol, C++ mangles it, and
# 25 sound ports are blamed for a header they never saw. run_freebsd_oracle
# .sh now probes exactly that and prints the answer; this floor stays at the
# measured 174 until it does.
174
